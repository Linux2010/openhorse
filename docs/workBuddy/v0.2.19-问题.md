## 二、静态扫描重点项（边界与健壮性）

> 本轮对 `JSON.parse`、类型断言、未处理 Promise 等做了抽样核查。此前报告点名的 5 处"崩溃/数据丢失"点经复核**均已修复或属误报**，见文末"历史误报复核"。当前真实发现的边界/健壮性缺陷如下。

### [P1] 测试依赖原生模块 ABI 与运行环境 Node 版本不匹配
- **文件/位置**: `node_modules/better-sqlite3`（依赖）；影响 `tests/vector.test.ts`、`tests/storage-maintenance.test.ts`
- **描述**: 见上方"测试失败根因"。非源码缺陷，属构建/运行环境不一致。
- **后果**: 内存向量检索、语义搜索、孤儿清理等依赖 SQLite 的**功能在当前 Node 环境下无法被测试覆盖**，且若以 Node 22 直接运行依赖该模块的产品代码同样会加载失败。
- **建议**: 在用于构建/测试/运行的同一 Node 版本下执行 `npm rebuild better-sqlite3`（或删除 `node_modules` 后用匹配版本的 Node 重装）；或在 CI 中固定 Node 版本（与编译原生模块时一致）。

### [P2] 浮空 Promise / 未处理拒绝
- **文件/行号**: `src/agents/worker-pool.ts:73`
- **描述**: 队列等待分支 `this.executeTask(workerId, task, forkOptions).then(resolve)` 没有 `.catch`。若 `executeTask` reject，会成为 unhandled rejection（Node 默认告警；`--unhandled-rejections=strict` 下可退出进程）。注意：同文件第 233 行的递归调用**已**加 `.catch()`，仅此处遗漏。
- **后果**: worker 空闲后领取队列任务执行失败时产生未处理拒绝告警，极端配置下可中断进程。
- **建议**: 改为 `.then(resolve).catch(err => resolve({ success: false, error: String(err), ... }))`，使其与外层 `setTimeout` 超时兜底语义一致。

### [P2] 大量 ESLint 警告（代码质量技术债）
- **文件/范围**: 全仓 `src/`，共 199 条
- **描述**: 见上方"Lint 警告分布"。以 `no-explicit-any`（类型安全弱化）与 `no-unused-vars`（死代码）为主。
- **后果**: 长期不治理会掩盖真实问题、增加维护成本；`any` 扩散会削弱 TypeScript 的静态保障。
- **建议**: 分批清理；`no-unused-vars`/`prefer-const` 大部分可用 `npm run lint -- --fix` 自动修复；`no-explicit-any` 与 `ban-ts-comment` 需按模块人工收窄类型。

### [P2] PTY / print 冒烟测试在沙箱中不稳定
- **文件/范围**: `tests/*-pty.test.ts`、`tests/print-mode.test.ts`、`tests/workspace-diff.test.ts`
- **描述**: 真实伪终端输出精确比对在 CI/沙箱下偶发失败（deep-equality mismatch / "PTY smoke failed after 3 attempts"）。
- **后果**: 可能掩盖真实 UI 回归，也可能因环境问题产生噪声红，降低巡检信号可信度。
- **建议**: 在带真实 TTY 的环境中人工复核这些用例是否代表真实回归；对纯环境噪声项考虑加 `jest.retry` 或拆出与终端无关的断言。
